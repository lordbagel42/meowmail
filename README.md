# Meow Mail

Receive-only temporary mail for Slack **#meow-mail**, deployed at https://temp.mrrpmraow.com. The service starts paused. No outbound email, account recovery, or attachment delivery.

## Current deployment status

Genuine Slack terms acceptance, mailbox creation, and incoming-mail delivery have been verified. **Automatic `gib email` event delivery is still unresolved:** recent genuine channel messages have no replies and no corresponding Worker HTTP invocation in the queried logs. A signed URL-verification control succeeds, but that does not establish automatic Events API delivery. This source upload does not fix that delivery issue or apply the proposed Cloudflare Browser Integrity Check exception.

Runtime credentials, encrypted local state, received mail, and deployment artifacts are not included in this repository. The Slack manifest is a bootstrap template, not an export of the live app's saved configuration.

## Activate privately

1. Open https://temp.mrrpmraow.com/admin and sign in with **me@raygen.dev** using Cloudflare Access's emailed code. Both Access and the Worker enforce this exact email.
2. In Setup & settings, follow the supplied Slack manifest link. Create a new Slack app from the manifest, install it, and invite it to #meow-mail. Do not reuse another service's credentials.
3. Save the Slack bot token, signing secret, and channel ID with **Allow new temporary addresses OFF**.
4. Enable Slack Event Subscriptions with request URL `https://temp.mrrpmraow.com/slack/events` and bot event `message.channels`. Interactivity uses `https://temp.mrrpmraow.com/slack/interactions`. The initial manifest omits event subscriptions entirely so the signing secret can be saved before Slack's URL verification.
5. Save a Tavily API key privately in the dashboard. Click **Connect Codex** to start a fresh 10-minute legacy browser callback flow. Open the provided OpenAI sign-in link in its new tab and approve using your own account. OpenAI redirects to `http://localhost:1455/auth/callback`; that local page may fail to load, which is expected. No local listener is required on your machine. Copy the **full callback URL from the browser address bar**, return to the owner-protected dashboard, paste it into **Private full localhost callback URL**, and click **Complete Codex connection**. Paste it only there, never into this thread, Slack, source files, or another site. If the flow expires or fails, refresh to verify status before starting a new flow. No device login or polling is used. Pi uses `openai-codex / gpt-6.1-terra` against your Codex subscription allowance with no paid API fallback. Tavily is separate.
6. Enable new addresses and save. This queues the welcome and pinned ban list. Post `gib email` in #meow-mail and accept the Slack terms button before an address is created. Test delivery with nonsensitive mail.

## Behavior and limits

- A random address lasts 24 hours. Mail is delivered as inert plain text to the requesting Slack thread and logged for operator review. Deleting the root request immediately revokes delivery, including out-of-order deletion events. Ban decisions revoke all the user's addresses.
- One active address and three newly created addresses per user per rolling 24 hours. At most 50 active/provisioning routes, 50 incoming messages/address/day, and 256 KiB/message. Long Slack bodies are truncated; full retained text remains available to the owner.
- All free trials, trial farming, limit evasion, fraud, spam, harassment and other abuse are prohibited. Acceptance is recorded per Slack user and terms version. Email content is retained for 90 days; audit/review evidence for 365 days. Slack retention is separately controlled by the workspace.
- `U085KKYFA6Q` is permanently excluded in code. The dashboard cannot unban that ID.
- Slack-attributed bot/app address requests immediately ban that actor, except owner `U08R4KDL6UF`. A bot does not identify its human operator; unrelated humans are not blamed. Automation using ordinary human credentials is indistinguishable from human Slack activity and cannot reliably be caught.
- Pi + Tavily runs daily at 08:00 UTC. It researches up to eight observed domains with a bounded agent loop. Tavily gets domains; OpenAI processes aggregate usage and attributed free-trial intent, never email bodies. The owner connects their own Codex subscription, not an API key. The callback input clears immediately upon submission and on disconnect; neither it nor the authorization code is persisted in browser storage. Access and refresh tokens never return to the browser. The backend enforces state/PKCE validation with one-time encrypted pending state; the encrypted grant stays on the backend. **Disconnect Codex** clears the stored grant and pauses mail; connection alone does not enable the service or create an address.
- Pi can independently ban with researched source URLs **only when local evidence includes an explicit Slack-signed free-trial address request**, such as `gib email for a free trial on example.org`. Such requests are refused an address. Sender domains, unsolicited mail, counts and web snippets alone cannot authorize a ban. Other concerns stay in the review log for the owner. This prevents people from framing recipients by emailing their public addresses.
- Service bans, not workspace bans, are announced in #meow-mail. The pinned list is updated. Reasons and evidence stay in the owner dashboard. Appeals go to me@raygen.dev.

## Local development and deployment

Use Node 22+ and pnpm. `pnpm install --frozen-lockfile`, `pnpm check`, `pnpm lint`, and `pnpm test`. Tests build first and run isolated workerd/SQLite with synthetic Slack, research, LLM and routing responses. `pnpm dev` is local-only; there is no production authentication bypass. For owner-access tests use the included synthetic signed-JWT integration fixture, not a weakened production auth path.

`pnpm format` formats source and public assets. `pnpm deploy` deploys the Worker, assets, Durable Object migration and daily cron from `wrangler.jsonc`. The account currently uses Workers Free defaults; no paid plan was enabled.

Runtime secrets are `CONFIG_KEY` and `CF_ROUTING_TOKEN`. The latter has only Email Routing Rules Read/Write on the mrrpmraow.com zone, not account-wide or global-key authority. Never rotate `CONFIG_KEY` without decrypting/re-encrypting saved configuration: it protects dashboard credentials and the Codex grant in Durable Object storage.

CLI deployments can provision the optional `SLACK_DEPLOYMENT` Worker secret with the new app's `slackToken`, `slackSigningSecret`, `channel`, `team`, and `botUser` as JSON. Install it directly through the deployment tooling, never through chat or tracked files. Encrypted dashboard settings override this deployment baseline. Provisioning Slack credentials does not enable mail or bypass Codex/Tavily setup; only an explicit validated dashboard save can enable the service.

An operator can provision `MEOW_MAIL_TAVILY_API_KEY` as a Worker secret; saved dashboard values override it. For an authorized one-time Pi login transfer, `CODEX_BOOTSTRAP` accepts `{id,credential}` with a fresh UUID v4 and only Pi's `openai-codex` OAuth entry. Send it directly from the source machine to Cloudflare, never through chat, artifacts, or tracked files. Startup imports a canonical encrypted grant only if none exists, preserves other settings, pauses mail, and clears pending callback state in one transaction. Existing grants are never overwritten. Durable consumed/skipped IDs survive disconnect, preventing a stale secret from reinstalling a credential. Confirmation appears as `config.codexImport` in the protected state API and credential-free `codex_bootstrap` telemetry after storage synchronization. Remove the bootstrap secret as soon as its matching terminal outcome is confirmed; never restore it during rollback. Markers cannot protect a database restored to before import. No network validation or refresh occurs during startup: structural consistency is not proof OpenAI accepts the session. Copying rotating refresh credentials does not create an independent login; simultaneous use by local Pi and this Worker can invalidate one copy. The importer never modifies or signs out local Pi.

Access and Email Routing DNS were provisioned separately. Access app `da4f44b2-237e-40de-b8f2-9c6a77788361` protects `temp.mrrpmraow.com/admin*`, allows only me@raygen.dev and uses email OTP. The backend additionally verifies JWT issuer/audience/signature/email. Email Routing subdomain `temp.mrrpmraow.com` is ready with its own MX records. Mailboxes use literal per-address routing rules, not a root-domain catch-all. Routing rules reconcile by their reserved `meow-mail:<address>` name after ambiguous API outcomes. Do not rename service-owned rules manually.

## Verification boundary

Runtime checks cover Access identity/audience, CSRF, signatures, streamed byte bounds, terms ownership, hardcoded/automation bans, mailbox expiry/revocation, inert delivery, duplicates, routing response loss, refusal of forged ban evidence and a real Pi loop using mocked Codex provider streams. Legacy callback checks reject invalid origin/state and replay, verify S256 challenge/verifier correspondence, exercise token refresh, serialize settings against disconnect, and enforce daily review deduplication. Rotated-refresh persistence is source-reviewed; a second real refresh is not verified. Browser checks cover empty/populated views, dialog focus/Escape, literal hostile content, setup errors, light/dark, narrow layout, and the legacy callback UI using synthetic authorization data. Public HTTPS, Access redirects, subdomain MX and creation/removal of a disposable Cloudflare mail route were checked after initial deployment. Slack installation, owner enable/save, genuine consent, mailbox creation, SMTP receipt, and a bounded authenticated Tavily search have since been verified live. The owner's Codex grant was privately imported, but live model entitlement, provider refresh, and a full scheduled research run remain unverified. Automatic Slack command delivery remains unresolved as described above. Disconnect clears local authorization and pauses mail; it does not revoke the grant at OpenAI or abort a review that already obtained its token.
